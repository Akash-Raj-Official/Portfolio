Weather Aggregator

A cloud-native Spring Boot service that aggregates forecasts and caches them. Containerised, tested in CI and published by GitHub Actions.

The idea

Many forecasts.One clear answer.

Search a city and get current conditions, a 24-hour temperature graph, an hourly strip and a 5-day outlook — in Celsius or Fahrenheit.

Behind it is a Spring Boot service that calls the weather provider, transforms the response, and caches it for 30 minutes so repeat searches are instant and API calls stay low.

What I built

A small service.Run like a big one.

  1. 01

    REST API at /api/v1/weather with current conditions, hourly and daily forecasts, and a clean 404 for unknown cities.

  2. 02

    Caching — case-insensitive cache lookups in an in-memory store with a 30-minute freshness window.

  3. 03

    Observability — Spring Boot Actuator health checks and a Prometheus metrics endpoint, ready for a Grafana dashboard.

  4. 04

    Secrets out of code — the API key moved to an environment variable, with tests that mock the external API.

Delivery

Commit.Test. Publish.

A multi-stage Dockerfile builds a small, non-root runtime image sized for a 1 GB instance. GitHub Actions runs the test suite on every push and pull request.

The public demo is a static build of the web UI on GitHub Pages that calls the free Open-Meteo API directly — no server to keep running, and no API key in the browser.
